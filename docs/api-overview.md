# API overview

## Назначение API

Task Tracker API предназначен для управления задачами, проектами, участниками проектов, комментариями, файлами, тегами и просмотра истории изменений задач.

API описывает MVP-версию сервиса. Некоторые сущности, например уведомления, могут присутствовать в модели данных, но не иметь методов в рамках MVP.

## Base URL

`https://api.task-tracker.example/v1`

## Формат данных

API принимает и возвращает данные в формате JSON.

Поля с датой и временем передаются в формате ISO 8601 `date-time`.

Пример:

`2026-10-01T17:00:00Z`

Поля, для которых время не требуется, передаются в формате ISO 8601 `date`.

Пример:

`2026-09-16`

## Авторизация

Защищённые методы требуют передачи токена в заголовке `Authorization`.

Пример:

```http
Authorization: Bearer <access_token>
```
## Идентификаторы

Идентификаторы сущностей передаются в path-параметрах
```http
GET /tasks/{taskId}
```
## Пагинация
Для методов, выводящих списки, используется cursor-based пагинация
```http
GET /tasks?limit=20&cursor=abc
```
## Фильтрация
Список задач можно фильтровать по статусу, приоритету, исполнителю, автору и крайнему сроку исполнения
```http
GET /tasks?status=analysis&assigned_user_id=42
```
Список пользователей можно фильтровать по логину пользователя
```http
GET /users?username=ivanov
```
Список проектов можно фильтровать по названию проекта и описанию
```http
GET /projects?project_name=optimization
```
## Идемпотентность

Для операций создания ресурсов используется заголовок `Idempotency-Key`.

Клиент должен передавать уникальный ключ для повторяемых POST-запросов, чтобы избежать создания дублей при повторной отправке запроса.

Пример:

```http
Idempotency-Key: 3fa85f64-5717-4562-b3fc-2c963f66afa6
```

## Формат ошибки
Ошибки возвращаются в едином формате
```json
{
  "error_code": "VALIDATION_ERROR",
  "message": "Invalid request parameters",
  "details": "Task name is required"
}
```
## Ограничения MVP
- API уведомлений не реализуется в рамках MVP.
- Внешняя доставка email/push-уведомлений не реализуется.
- Хранение файлов описано упрощённо: API принимает файл, но в модели данных сохраняется ссылка на файл. Реальное файловое хранилище не детализируется в рамках MVP.
- Удаление сущностей не реализуется, если не указано отдельно.
