# Доменная модель

Task Tracker —  сервис для управления задачами в личных и рабочих пространствах.

Сервис позволяет пользователям создавать задачи, объединять их в проекты, назначать исполнителей, добавлять комментарии, файлы, теги, получать уведомления и отслеживать историю изменений.

## Основные сущности

| Сущность | Назначение |
|---|---|
| User | Пользователь системы. Может создавать задачи и проекты, быть участником проектов, исполнителем задач и получателем уведомлений. |
| Project | Проект, объединяющий задачи. Задача может быть создана без проекта и добавлена в проект позже. |
| Task | Основная рабочая единица системы. Содержит описание, статус, приоритет, дедлайн, автора и, при наличии, исполнителя. |
| Comment | Комментарий пользователя к задаче. |
| File | Файл, прикреплённый к задаче. |
| Tag | Метка для группировки и поиска задач. |
| Notification | Уведомление пользователя о событиях по задаче. |
| ActivityLog | Журнал событий и изменений по задаче. |
| Role | Роль пользователя в проекте. |
| Permission | Право доступа, связанное с ролью. |


## Ассоциативные таблицы

| Таблица | Назначение |
|---|---|
| task_tags | Связывает задачи и теги. Одна задача может иметь несколько тегов, один тег может использоваться в нескольких задачах. |
| project_members | Связывает пользователей, проекты и роли. Определяет роль пользователя в конкретном проекте. |
| role_permissions | Связывает роли и права доступа. |

## Справочники

| Справочник | Назначение | Примеры значений |
|---|---|---|
| task_statuses | Возможные статусы задачи | backlog, analysis, in_progress, testing, ready_to_release, released, trashed |
| project_statuses | Возможные статусы проекта | new, analysis, in_progress, done, cancelled  |
| notification_statuses | Статусы уведомления | new, sent, delivered, failed |
| priorities | Приоритеты задачи | low, medium, high, blocker |
| event_types | Типы событий в журнале изменений | task_created, status_changed, comment_added, file_added |

## Основные связи

- Пользователь может создать несколько задач, каждая задача имеет одного автора.
- Задача может иметь исполнителя, но исполнитель не обязателен.
- Проект может содержать несколько задач, при этом задача может существовать без проекта.
- Задача может иметь несколько комментариев, файлов, тегов и уведомлений.
- История изменений ведётся по каждой задаче. При создании задачи создаётся первая запись в таблице activity_log.
- Пользователь может быть участником нескольких проектов.
- В рамках одного проекта пользователь имеет одну роль.

## Ключевые бизнес-правила

- Задача может быть создана без проекта.
- У задачи всегда есть автор, статус и приоритет.
- Исполнитель в задаче необязателен.
- Уведомления формируются только по событиям задач.
- Журнал событий (activity_log) ведётся только по задачам.
- При создании задачи система создаёт первую запись в журнале событий.
